\title[Shortcut-controlled evaluation of PHP web-shell detection]{Beyond Reported F1: A Shortcut-Controlled Evaluation of Program-Graph PHP Web-Shell Detection and the Limited Role of Learned Taint}

\author*[1]{\fnm{Anh} \sur{Hoang}}\email{anhh@ueh.edu.vn}
\author[1]{\fnm{Hoang Gia} \sur{Dinh}}\email{giadh@ueh.edu.vn}
\affil*[1]{\orgname{University of Economics Ho Chi Minh City (UEH)}, \orgaddress{\city{Ho Chi Minh City}, \country{Vietnam}}}

\abstract{\textbf{Purpose:} Learned PHP web-shell detectors routinely report
near-ceiling scores, yet such scores do not show that a detector has learned
malicious program behavior: source collections, benign coding style, file
statistics, and payload packaging can all act as shortcuts.
\textbf{Methods:} We contribute a shortcut-controlled evaluation protocol that
combines near-duplicate-aware, cluster-disjoint partitions; input
canonicalization; shallow and graph-metadata probes reported as baselines; a
character-matched diagnostic subset; static deobfuscation; a two-sided
obfuscation matrix that transforms benign and malicious files alike and
separates structure-preserving from packaging transformations; a
source-disjoint holdout; and precision at low deployment prevalences. We apply
it to HiPaG, a hierarchical program-graph model (statement, function, file)
with a learned taint-dependency predictor.
\textbf{Results:} HiPaG reaches \HiPaGTestFOneMacro\ macro-F1 on the
in-distribution test split, but a random forest on shallow character statistics
already reaches
\RqOneShallowTestFOneMacro\ and a fine-tuned CodeBERT reaches
\RqOneCodeBertTestFOneMacro: most of the in-distribution score is available
without program structure, and the highest in-distribution score needs none of
it. The ranking does not survive the source shift, where CodeBERT falls to the
lowest PR-AUC of all models we ran (\RqOneCodeBertHoldoutPrAuc), below the
shallow probe, and HiPaG retains the highest (\HiPaGHoldoutPrAuc) --- a
difference no shared-split comparison would reveal. Learned taint edges are
largely redundant: they perform on par with
hand-written rule edges and with no semantic edges on clean data, help only
narrowly under identifier renaming, and do not help under packaging or
variable-function rewriting.
\textbf{Conclusion:} Web-shell detection results should be reported together
with shortcut probes, transformation families, source shift and base-rate
precision; learned taint should not be presented as the key to detection.}

\keywords{PHP web-shell detection, Shortcut learning, Evaluation methodology, Program graphs, Taint analysis, Obfuscation}

\section{Introduction}\label{sec:intro}
Web shells are a documented, high-severity threat. The MITRE ATT\&CK framework
catalogues web-shell deployment as technique T1505.003, national agencies have
issued dedicated guidance on detecting and preventing web-shell
malware,\footnote{NSA \& ASD, \emph{Detect and Prevent Web Shell Malware}, 2020.}
and web-shell deployment is a documented stage of actively exploited
vulnerabilities such as CVE-2021-26855 (ProxyLogon).\footnote{\url{https://www.cisa.gov/news-events/cybersecurity-advisories/aa21-062a}}
The underlying weaknesses---unrestricted file upload (CWE-434), code injection
(CWE-94) and OS command injection (CWE-78)---remain long-standing entries in
CWE and the OWASP Web Security Testing Guide.

Learning-based PHP web-shell detectors have been proposed on lexical, opcode,
syntax-tree and graph representations~\cite{survey2024,astdf2024,glareshell2024},
and many report near-ceiling accuracy on their own datasets. A high score on a
conventional split, however, does not reveal \emph{what} the classifier has
learned. Public web-shell collections and benign corpora differ in source,
age, coding style, file size, character statistics, and in whether code is
packed inside an \texttt{eval}/decoder wrapper. Each of these differences can
be exploited by a classifier without any notion of malicious data flow---a
manifestation of shortcut learning~\cite{geirhos2020shortcut} and of the
evaluation pitfalls documented for machine learning in
security~\cite{arp2022dos,pendlebury2019tesseract}.

This paper asks whether reported PHP web-shell detection performance remains
informative once such shortcuts are controlled, and what a structurally
motivated model actually gains under those controls. Our answer is
deliberately measured. We find that \emph{most of the in-distribution
performance is attainable from shallow features}: a random forest on character
statistics of canonicalized source comes within a few points of every learned
model. On the in-distribution split a fine-tuned CodeBERT, which uses no
program graph at all, matches or exceeds the hierarchical model on macro-F1 and
in the low-false-positive regime alike, trailing it only on PR-AUC and by a
margin well inside the seed-to-seed spread. The one advantage
that does distinguish the structural model is slightly better ranking on the
source-disjoint holdout, and even that is modest and short of what deployment
would require. A learned taint-dependency predictor, which motivated the
model, turns out to be largely redundant.

\paragraph{Contributions.}
\begin{itemize}
  \item \textbf{A shortcut-controlled evaluation protocol} for PHP web-shell
  detection (Section~\ref{sec:protocol}, our main contribution). Each component
  targets a specific route to inflated scores: near-duplicate and source
  leakage, coding style, coarse file and parser statistics, character
  distributions, the ``wrapper equals malware'' shortcut, and balanced-split
  optimism. Shortcut probes are reported as baselines, and obfuscation is
  applied to both classes and split into structure-preserving and packaging
  families.
  \item \textbf{HiPaG}, a hierarchical multi-relational program-graph model
  (statement $\rightarrow$ function $\rightarrow$ file) with a token-sequence
  transformer, intra-function GATv2, an inter-procedural graph transformer,
  static deobfuscation, and a weakly supervised taint-dependency predictor with
  strict labels, permissive candidates and inter-procedural bridges
  (Section~\ref{sec:method}). We describe the mechanism without claiming that
  it determines performance.
  \item \textbf{An honest account of learned taint.} Against a pre-specified
  falsification criterion, learned semantic edges are on par with hand-written
  rule edges and with their removal on clean data, help only narrowly under
  identifier renaming, and do not help under packaging or variable-function
  rewriting (Section~\ref{sec:results}). We report this negative result
  directly, together with the baselines we could not reproduce.
\end{itemize}

\section{Related Work}\label{sec:related}
\subsection{PHP web-shell detection}
Early learned detectors treat a script as a sequence of opcodes or tokens and
classify it with convolutional or recurrent networks, a line summarized in a
recent survey~\cite{survey2024}; more recent work handles long scripts with
sliding-window attention~\cite{wang2025slidingwindow}. Structural detectors
operate on abstract syntax trees, for example AST features with a deep
forest~\cite{astdf2024}, or on control-flow graphs. The nearest neighbour to
our model is GlareShell~\cite{glareshell2024}, which builds a flat
interprocedural control-flow graph, attaches hand-assigned risk levels to
statements and classifies it with a graph neural network. Work on evasion
studies obfuscated and generated web shells and multimodal feature
fusion~\cite{mmfdetect2025}; concurrent work co-evolves web-shell generation
with multi-view detection for robustness~\cite{ding2026shellforge} and
benchmarks fine-grained web-shell family classification~\cite{han2025familyclass}.
Published detectors are typically evaluated on their own datasets and splits,
so their reported numbers are not directly comparable with each other or with
ours; cross-dataset generalization in particular is rarely evaluated, including
for recent large-language-model detectors~\cite{han2025llmwebshell}, and we
therefore compare only against baselines run on our split
(Section~\ref{sec:setup}).

\subsection{Program graphs and taint}
Static taint analysis for PHP tracks user-controlled sources to sensitive
sinks with hand-written rules~\cite{jovanovic2006pixy}. Code property graphs
merge syntax, control and data flow into one multi-relational
graph~\cite{yamaguchi2014cpg}, and graph neural networks over such program
graphs have been used for program understanding~\cite{allamanis2018graphs} and
vulnerability detection~\cite{zhou2019devign}. Our encoder uses
GATv2~\cite{brody2022gatv2} and a graph-transformer
layer~\cite{shi2021unimp}, and our taint predictor follows the link-prediction
view of learning edges from node states~\cite{zhang2018seal}.

\subsection{Shortcuts and evaluation pitfalls in security ML}
Shortcut learning describes models that succeed through spurious decision
rules that do not transfer~\cite{geirhos2020shortcut}. In security, Arp et al.\
catalogue pitfalls including sampling bias, data snooping, spurious
correlations and base-rate neglect~\cite{arp2022dos}; TESSERACT shows how
spatial and temporal bias inflate malware-classifier
results~\cite{pendlebury2019tesseract}; and leakage is a widespread cause of
irreproducible machine-learning results~\cite{kapoor2023leakage}, and shortcut
cues have been documented directly in a neighbouring security task, encrypted
network-traffic classification~\cite{wang2026shortcuttraffic}. Code
duplication inflates the measured performance of models of
code~\cite{allamanis2019duplication}, a concern also recognized for web-shell
datasets~\cite{hannousse2022webshell}; learned vulnerability detectors lose
much of their reported accuracy under realistic
evaluation~\cite{chakraborty2022deep,risse2024limits}. The base-rate fallacy
makes precision at realistic prevalence the decisive operational
quantity~\cite{axelsson2000base}, and precision--recall analysis is more
informative than ROC analysis under imbalance~\cite{saito2015prc}. Recent
PHP web-shell detectors pursue directions such as feature fusion with federated
learning~\cite{zeng2025webshell} and incremental learning~\cite{wang2025incremental},
but to our knowledge these evaluation concerns have not been operationalized
together for PHP web-shell detection; this is the gap our protocol addresses.

\section{Threat Model}\label{sec:threat}
\paragraph{Setting.} The unit of analysis is one PHP source file. The detector
parses it, never executes it, and outputs a web-shell score; the target use is
static scanning of repositories, uploads and deployment pipelines.

\paragraph{Adversary.} The adversary controls the content of the malicious
file and applies semantics-preserving transformations to evade detection:
identifier renaming, dead-code insertion, comment and whitespace changes,
string splitting and concatenation, variable functions, and payload packaging
with \texttt{base64\_decode}, \texttt{gzinflate} or nested decoders inside
\texttt{eval}. Benign developers may also pack, minify or encode legitimate
code, so a wrapper alone is not evidence of malice.

\paragraph{Out of scope.} We do not model a white-box adaptive adversary who
optimizes inputs against the model, nor training-data poisoning, nor runtime
behavior. Static analysis has a principled boundary: when the payload exists
only as data reconstructed at run time from inputs, no static detector can
recover it. We treat packaging as that boundary and report it as such rather
than as a robustness claim. Every sample in our corpus is a single file;
multi-file web shells linked by \texttt{include} are therefore not evaluated
(Section~\ref{sec:threats}).

\paragraph{Detection target.} The behavior of interest is a dependency from an
attacker-controlled source (e.g.\ \texttt{\$\_POST}) to a code- or
command-execution sink (e.g.\ \texttt{eval}, \texttt{system}). Whether a
detector actually relies on this dependency, rather than on correlated surface
cues, is exactly what the protocol of Section~\ref{sec:protocol} is designed
to test.

\section{HiPaG}\label{sec:method}
HiPaG lowers each file to a hierarchical multi-relational graph and classifies
it with a three-tier encoder (Fig.~\ref{fig:arch}). Semantic source-to-sink
edges are produced in the forward pass by a taint-dependency predictor; the
graph builder only stores candidate pairs and weak labels. We describe the
mechanism in full, but the experiments in Section~\ref{sec:results} show that
the predictor is not what determines detection performance.

\subsection{Parsing, canonicalization and static deobfuscation}\label{sec:parse}
Files are parsed with nikic/PHP-Parser.\footnote{\url{https://github.com/nikic/PHP-Parser}}
Before parsing, source text is canonicalized at the token level: comments and
documentation comments are removed, a trailing closing tag is dropped, and
line endings are normalized inside whitespace tokens; string contents,
heredocs and inline HTML are untouched. The model and the shallow probe see
the same canonical text (Section~\ref{sec:p-canon}). Files that fail to parse
are kept with a minimal graph and an explicit parse status rather than
silently removed.

A static deobfuscator unwraps common packaging without executing anything. It
constant-folds expressions built from string literals, concatenation of
literals, and nested calls to a fixed table of decoders (base64, gzip family,
rot13, hex, URL and uu decoding), folding from the innermost call outwards. A
narrow constant propagation substitutes variables that are assigned exactly
once from a literal in the same scope. A decoded string is accepted as code
only if it parses without error and yields at least one real statement; the
resulting statements are grafted into the graph and flagged as deobfuscated.
Decoding depth and intermediate sizes are bounded, and gzip-family inputs are
decompressed incrementally so that a decompression bomb is never materialized.
Arguments that are not compile-time constants, for example values read from a
request, are left untouched; this is the static boundary of
Section~\ref{sec:threat}.

\subsection{Hierarchical program graph}\label{sec:graph}
For a file we build statement nodes and code-unit nodes (one per function or
method plus the top-level script), with seven relation types:
$E_{\text{seq}}$ (consecutive statements), $E_{\text{skip}}$ (short forward
skips within a small window), $E_{\text{cfg}}$ (control flow from the
structured statements of each code unit), $E_{\text{dfg}}$ (def--use edges from
reaching definitions), $E_{\text{sem}}$ (predicted source-to-sink
dependencies), $E_{\text{call}}$ (calls to functions defined in the same file),
and $E_{\text{include}}$ (include relations between code units). The
control-flow graph is approximate (no exception or \texttt{goto} edges), and
array-element and property writes count as definitions of the base variable.
Because each sample in our corpus is a standalone file, include targets outside
the file cannot be resolved and $E_{\text{include}}$ is empty in all reported
experiments; the file level thus reduces to the call graph.

Statement features comprise a one-hot statement kind; multi-hot flags for seed
sources, sinks and decoders; a flag for statements that contain both a source
and a sink (e.g.\ \texttt{eval(\$\_POST['c'])}); character entropy, length and
relative position; and the statement's token sequence. A small vector of
file-level indicators (entropy and the presence of \texttt{eval}-like calls,
decoders and variable functions) is passed to the classification head.

\subsection{Seeds: strict labels, permissive candidates}\label{sec:seeds}
Sources are the PHP superglobals and request-reading APIs, including legacy
input arrays. Sinks are split into two lists. \emph{Strict} sinks (code and
command execution, dynamic callables, \texttt{unserialize}, and
context-dependent sinks: \texttt{include}/\texttt{require} with a non-constant
argument and \texttt{preg\_replace} with the \texttt{/e} modifier) are the only
sinks used to create positive labels. \emph{Candidate-only} sinks (file write,
upload move, network and mail functions, \texttt{fopen} in a write mode,
\texttt{extract}, and \texttt{ob\_start} with a variable callback) may form
candidate pairs but never labels. A sink name counts only when it is the callee
of an actual call node or language construct in the syntax tree; string
literals or identifiers that merely spell a sink name, as in
\texttt{\$f = 'assert'}, are not sinks. Calls through a variable are mapped to
a dynamic-call sink.

\subsection{Candidate pairs and weak labels}\label{sec:cands}
Within a code unit, a \emph{generic} candidate is any ordered statement pair
$(i,j)$ with $j$ reachable from $i$ within $H=\HPcandidateHops$ hops over
$E_{\text{seq}}\cup E_{\text{cfg}}\cup E_{\text{dfg}}$. A \emph{typed}
candidate additionally has a source at $i$ and a strict or candidate-only sink
at $j$. Typed candidates also cross code units through two bridges bounded by
$D=\HPinterprocDepth$ call hops: an \emph{argument bridge} links a source in a
caller to a sink in a callee when the tainted value is passed as the argument
whose parameter reaches the sink, and a \emph{return bridge} links a source in
a callee whose tainted value reaches a \texttt{return} to a sink in the caller
that consumes the call result. A bridge is \emph{exact} when call arguments,
parameters and def--use information are all available, and a \emph{fallback}
otherwise; no bridge is created merely because one function calls another. The
candidate set is capped at $C_{\max}=\HPmaxCand$ pairs per file, keeping typed
candidates first and filling the remainder by uniform sampling of generic
candidates.

Positive labels are only (source, strict sink) pairs connected by an in-unit
path or an exact bridge. Negatives are sampled at $\rho=\HPnegPerPos$ per
positive, half from non-positive candidates (hard negatives) and half from
other pairs; typed pairs are never used as negatives, because a typed pair
without a label may still be a true dependency. These labels mark
\emph{reachable} seed pairs, not verified dynamic taint flows.

\subsection{Taint-dependency predictor}\label{sec:taint}
For statement states $h_i,h_j$ after tier one, the predictor scores a directed
candidate,
\begin{equation}
p_{ij}=\sigma\!\left(\mathrm{MLP}([\,h_i \Vert h_j\,])\right).
\end{equation}
An edge $i\rightarrow j$ enters $E_{\text{sem}}$ when $p_{ij}$ exceeds
$\max(\tau,\tau_{\min})$ and is among the $k$ highest-scoring candidates with
destination $j$. The threshold $\tau$ is recalibrated on validation data after
each epoch to maximize edge-level F1 against the weak labels, with floor
$\tau_{\min}=\HPtauFloor$; the per-sink budget is $k=\HPtopK$. Selected edges
carry $p_{ij}$ as an edge attribute, so the detection loss also reaches the
predictor through these weights. Training minimizes
\begin{equation}
\mathcal{L}=\mathcal{L}_{\mathrm{det}}+\lambda\,\mathcal{L}_{\mathrm{taint}},
\qquad \lambda=\HPlambdaTaint,
\end{equation}
where $\mathcal{L}_{\mathrm{taint}}$ is a binary cross-entropy over positive
and negative pairs whose positive weight is set per batch to
$N_{\text{neg}}/N_{\text{pos}}$; without it, probabilities collapse toward the
class prior, fall below $\tau_{\min}$ and $E_{\text{sem}}$ becomes empty. For
the first $W=\HPwarmup$ epochs tier two receives the rule edges (positive pairs
restricted to the candidate set and the same budget) while the predictor is
trained; afterwards the predicted edges replace them. The same rule edges form
the \emph{rule} ablation, so the learned-versus-rule comparison is made over an
identical candidate universe. It tests the value of learned \emph{scoring} of
candidates, not of candidate generation beyond static reachability.

\subsection{Three-tier encoder}\label{sec:encoder}
\emph{Tier one} embeds each statement's hashed token sequence with a
transformer encoder~\cite{vaswani2017attention} and masked mean pooling, then
concatenates the result with the statement features. \emph{Tier two} applies
GATv2~\cite{brody2022gatv2} over $E_{\text{seq}}$, $E_{\text{skip}}$,
$E_{\text{cfg}}$, $E_{\text{dfg}}$ and $E_{\text{sem}}$ jointly; each edge
carries a one-hot relation type and a weight ($p_{ij}$ for semantic edges, one
otherwise), so attention is relation-aware. \emph{Tier three} max-pools
statements into code units and applies graph-transformer
layers~\cite{shi2021unimp} over $E_{\text{call}}$ and $E_{\text{include}}$ with
root connections. Code units are max-pooled into a file vector, concatenated
with the file-level indicators, and classified by a two-layer MLP.

produce the reported score without the detector modelling malicious program
behavior, and how is each one controlled or exposed?} Table~\ref{tab:protocol}

\subsection{Partitioning and source holdout}\label{sec:p-split}
Exact duplicates are removed after canonicalization (groups with conflicting
labels are discarded entirely), and near-duplicates are grouped by MinHash
locality-sensitive hashing~\cite{broder1997resemblance} over canonical token
shingles, confirmed by estimated Jaccard similarity and merged into clusters.
Train, validation and test partitions are assigned by cluster and stratified
by label and dominant source, so variants of one shell never appear on both
sides~\cite{allamanis2019duplication}. A separate collection is held out
entirely; clusters of that collection that touch the training pool are removed.
The holdout is source-disjoint but belongs to the same broad family of PHP web
shells, so it measures transfer between collections, not cross-family
generalization.

\subsection{Canonicalization}\label{sec:p-canon}
Comments, documentation blocks, trailing tags and line-ending conventions
differ systematically between benign projects and web-shell collections and can
be learned as labels. Canonicalizing the text seen by every model and probe
removes these cues by construction. A practical consequence is that comment
insertion, a common ``obfuscation level'' in prior evaluations, becomes a
no-op and is not reported as a robustness result.

\subsection{Shortcut probes as baselines}\label{sec:p-probe}
Two random forests~\cite{breiman2001rf} quantify how much discrimination is
available without program semantics. The \emph{shallow} probe uses byte- and
character-level statistics of the canonical text (size, line structure,
entropy, character-class fractions, long base64-like runs, tag and namespace
usage); it deliberately excludes sink and source names. The
\emph{graph-metadata} probe uses only by-products of parsing and graph
construction (parse status and counts of statements, functions, edges, roles
and candidates). Probes are evaluated with cluster-grouped cross-validation and
with the same train-to-test, train-to-holdout and per-obfuscation-level
transfers as the models, and they appear as baselines in every result table.
A strong probe is a warning, not a competitor: it shows how much of a score
could be explained without the reasoning a structural model claims.

\subsection{Distribution matching and the character-matched subset}\label{sec:p-char}
Benign files are sampled with weights that match the joint distribution of file
size and byte entropy of the training web shells, and a hard-benign subset
contains legitimate code that uses sinks or decoders. A fraction of benign
files are added as minified or packed variants so that packing is not a class
marker. As a stricter diagnostic, the character-matched subset pairs structured
web shells one-to-one with nearest-neighbour benign files on character features
(entropy, digit fraction, log size, base64 presence) within a caliper, so that
the shallow probe is close to chance on it. Matching never uses graph or taint
information.

\subsection{Two-sided obfuscation matrix}\label{sec:p-obf}
Test files of \emph{both} classes are transformed at levels L0--L5 and never
used for training or model selection. Structure-preserving levels change
surface form while keeping control and data flow: L1 renames identifiers and
inserts dead code, and L4 rewrites direct calls as variable-function calls
built from string fragments. Packaging levels move the program into a string
that is decoded at run time: L2 (base64), L3 (gzinflate) and L5 (multi-layer).
L0 is the untransformed test set. Transforming benign files as well is
essential: if only web shells were wrapped, a detector could score well on
packaging levels simply by flagging wrappers. A transformation that breaks a
file that originally passed the PHP linter is recorded and excluded.
Structure-preserving levels test whether a detector uses structure; packaging
levels mark the static-analysis boundary.

\subsection{Metrics and statistical reporting}\label{sec:p-metrics}
We report macro-F1, accuracy, precision, recall, MCC, PR-AUC, FPR at 95\% TPR,
and precision at deployment prevalences of 10\%, 1\% and 0.1\%. Base-rate
precision is computed from the operating point at the target TPR, so it is a
prevalence adjustment rather than an observed precision on a deployment
stream~\cite{axelsson2000base}. Every configuration is trained with several
seeds (counts are given with each table) and reported as mean and sample
standard deviation.

\subsection{Pre-specified falsification criterion}\label{sec:p-c11}
Before training we fixed a criterion for the claim that learned semantic edges
matter: the claim is rejected if the full model exceeds the no-semantic-edge
model by less than \CElevenMargin\ macro-F1 points at every obfuscation level
with overlapping confidence intervals across seeds. Fixing the criterion in
advance prevents the selective reporting of a favorable level.

\section{Experimental Setup}\label{sec:setup}
\paragraph{Data.} Web shells come from three public collections (Tennc,
JohnTroony, Cycle183); benign files come from a broad set of open-source PHP
applications and libraries pinned to fixed commits. The partitions contain
\NTrainPos/\NTrainNeg\ (web shell/benign) training, \NValPos/\NValNeg\
validation and \NTestPos/\NTestNeg\ test files, with \NHardBenignTest\
hard-benign files in the test split. The c01dsnap collection (\NHoldoutPos\ web
shells, \NHoldoutNeg\ benign files) forms the source-disjoint holdout; its
prevalence differs from the test split, so its macro-F1 is not directly
comparable and base-rate precision is the more meaningful cross-split quantity.

\paragraph{Baselines run.} On the same split we run the shallow and
graph-metadata probes, a bidirectional LSTM~\cite{hochreiter1997lstm} over
hashed parser tokens, and a flat GATv2 over the same statement graph without
hierarchy or semantic edges. The latter two are controlled local baselines,
not reproductions of named systems. We also fine-tune
CodeBERT~\cite{feng2020codebert} (\texttt{microsoft/codebert-base}) on the same
canonical text and the same split: files longer than the encoder limit are read
as sliding windows of 512 tokens with stride 384, of which only the first eight
are kept, so the tail of the longest \CodeBertTruncatedTrainPct\% of training
files is never seen. The file representation is the mean, across a file's
windows, of the per-window pooled \texttt{[CLS]} vector (the encoder's
\texttt{pooler\_output}: a dense projection of \texttt{[CLS]} followed by
$\tanh$), not a mean over token states. Training uses AdamW at a
learning rate of $2\times10^{-5}$, with the checkpoint selected by validation
PR-AUC and early stopping (patience 5, at most 25 epochs), over the same
\RqOneSeeds\ seeds.

\paragraph{Baselines not run.} An opcode-CNN baseline was not run because a PHP
opcode dumper was not available in our environment;
GlareShell~\cite{glareshell2024} was not reproduced because
its implementation, its manually assigned risk dictionary and its graph
preprocessing are not available, and our rule-edge ablation is not a GlareShell
reproduction; YARA was not run because no pinned PHP web-shell rule set and
executable were available. These omissions limit the comparison and are not
evidence that HiPaG outperforms those systems.

\paragraph{Training.} Models are trained with AdamW; the checkpoint is selected
by validation PR-AUC with early stopping, never in the warm-up phase. Taint
hyper-parameters ($k$ and $W$, with $\tau_{\min}$ fixed) were chosen on
validation macro-F1 by a separate sweep before any test evaluation. Complete
hyperparameters for every model are listed in Appendix~\ref{app:hparams}; the
full run manifest (library versions, data hashes and per-seed fingerprints) is
released as \texttt{repro/manifest.json} with the code.

\paragraph{Research questions.} \textbf{RQ1}: how does HiPaG compare with the
probes and local baselines on the test split? \textbf{RQ2}: how do the full,
rule-edge and no-semantic-edge variants behave across obfuscation levels (RQ4
checkpoints, inference only)? \textbf{RQ3}: how well do models transfer to the
source-disjoint holdout? \textbf{RQ4}: which components matter in a clean-split
ablation? \textbf{RQ5}: which taint hyper-parameters does the validation sweep
select?

\section{Results}\label{sec:results}

\subsection{Shortcut probes}\label{sec:r-probe}
The probes confirm that the task, as commonly posed, is largely
shortcut-solvable. Under cluster-grouped cross-validation the shallow probe
reaches an AUC of \ProbeShallowAucCV\%, and trained on the training split it
reaches \ProbeShallowAucTest\%\ on test and \ProbeShallowAucHoldout\%\ on the
holdout; the graph-metadata probe reaches \ProbeGraphmetaAucTest\%\ on test. The
probes also behave as the transformation families predict. Variable-function
rewriting barely moves the character statistics, and the shallow probe keeps an
AUC of \ProbeShallowAucLFour\%\ at L4 (\ProbeShallowAucLOne\%\ at L1). Under
packaging, where both classes are wrapped, the shallow probe's AUC falls sharply
to \ProbeShallowAucLTwo\%\ (L2) and \ProbeShallowAucLFive\%\ (L5). The
graph-metadata probe does \emph{not} collapse in the same way
(\ProbeGraphmetaAucLTwo\%\ at L2 and \ProbeGraphmetaAucLFive\%\ at L5), because the
static deobfuscation of Section~\ref{sec:parse} restores enough structure for
the parser-derived counts to stay discriminative; this is a property of the
pipeline, not evidence that the detector reasons about flow. The static
deobfuscation is directly responsible: with it disabled, every packaged file
reduces to the same one-statement wrapper graph, so graph metadata carries no
information and the probe is at chance under packaging
(\ProbeGraphmetaNoDeobfAucLTwo\%\ at L2, \ProbeGraphmetaNoDeobfAucLFive\%\ at L5),
whereas on clean data the two branches are almost identical
(\ProbeGraphmetaNoDeobfAucTest\%\ without versus \ProbeGraphmetaAucTest\%\ with
deobfuscation). A learned detector that merely matches the shallow probe on L0
and L4 therefore provides no evidence of structural reasoning by those numbers
alone.

\subsection{RQ3: source-disjoint holdout}\label{sec:r-rq3}
All models lose performance on the c01dsnap holdout (Table~\ref{tab:rq1}, lower
block). HiPaG keeps the highest mean macro-F1 (\HiPaGHoldoutFOneMacro) and
PR-AUC (\HiPaGHoldoutPrAuc, against \RqOneFlatGatvTwoHoldoutPrAuc\ for the flat
GATv2 and \RqOneShallowHoldoutPrAuc\ for the shallow probe). The ordering of
the in-distribution comparison does not survive the source shift: CodeBERT,
the strongest model on the test split, has the \emph{lowest} holdout PR-AUC of
all models we ran (\RqOneCodeBertHoldoutPrAuc), below even the shallow
character probe, and its threshold-dependent behaviour becomes erratic: its FPR
at 95\% TPR (\RqOneCodeBertHoldoutFprAtTprNineFive) varies across seeds by more
than its own mean, and its precision at 1\% prevalence
(\RqOneCodeBertHoldoutPrecAtBaseOnePct) carries a seed spread of more than half
the mean, so neither supports a stable operating point. A strongly
pretrained text encoder thus fits the in-distribution cues well and ranks
poorly off-distribution, which is exactly the failure mode a shared-split
comparison hides. HiPaG's own
low-false-positive advantage largely disappears as well: its FPR at 95\% TPR
(\HiPaGHoldoutFprAtTprNineFive) is comparable to those of the shallow probe and
the flat GATv2, and so is its precision at 1\% prevalence. At the default
threshold the loss is mainly in recall (\HiPaGHoldoutRecall) rather than
precision (\HiPaGHoldoutPrecision). The structural model therefore transfers
somewhat better in ranking quality, but not to a degree that would justify a
claim of robust deployment detection on unseen sources.

\subsection{RQ2: obfuscation matrix}\label{sec:r-rq2}

semantic-edge variants (full metrics in Appendix~\ref{app:full}), and
Fig.~\ref{fig:obf} plots macro-F1 by level. Two patterns stand out. First,
behavior depends on the transformation family rather than on a single
difficulty scale: the structure-preserving levels L1 and L4 cost a few points,

do not provide a consistent benefit. The no-semantic-edge variant has an equal

has the higher mean at L1, where it also leads the rule variant, and its leads
at L0 and L5 are small relative to the seed variation. Learned and rule edges
alternate in rank across levels, again within seed variation.

\paragraph{Falsification criterion.} At every level except L1 the full model
exceeds the no-semantic-edge model by less than the pre-specified margin or not
at all. At L1 the mean difference exceeds the margin, so the ``every level''
clause is formally not met; however, the seed confidence intervals of the two
variants overlap at L1, and the effect is absent or reversed at the other
structure-preserving level, L4. We therefore classify the outcome as
\emph{not supporting} the claim that learned semantic edges matter, with a
narrow, statistically unconfirmed exception for identifier renaming.

\subsection{RQ4: component ablation}\label{sec:r-rq4}
Table~\ref{tab:rq4} shows the clean-split ablation; the full metric set is in
Appendix~\ref{app:full} (Table~\ref{tab:rq4-full}). No single removal lowers
mean macro-F1 by more than the seed variation; removing the inter-procedural
tier, data-flow edges or replacing learned with rule edges leaves the mean
equal or higher. Learned semantic edges are thus redundant on clean data: the
full model (\RqFourFullTestFOneMacro), the rule variant
(\RqFourRuleESemTestFOneMacro) and the variant without semantic edges
(\RqFourNoESemTestFOneMacro) are indistinguishable within seed variation. The
one component whose removal consistently degrades the ranking-based and
base-rate metrics is max pooling: mean pooling gives the lowest PR-AUC and
precision at low prevalence. This suggests that the decisive signal is often
localized in a few statements, which a max-pooled hierarchy preserves.

\subsection{RQ5: taint hyper-parameters}\label{sec:r-rq5}
The validation sweep over the per-sink budget $k$ and the warm-up length $W$
($\tau_{\min}$ fixed) selected $k=\RqFiveChosenTopK$ and
$W=\RqFiveChosenWarmupEpochs$, with validation
macro-F1 \RqFiveValFOneMacro\ over \RqFiveSeeds\ seeds. The spread across the
grid was within seed variation, consistent with the small influence of the
semantic edges reported above. This is a selection result, not a test-set
estimate.

\subsection{Character-matched diagnostic}\label{sec:r-char}
On the character-matched subset (\CharMatchedPairs\ pairs) the shallow probe
reaches an AUC of only \CharMatchedShallowAuc\%, so character cues are largely
removed; the graph-metadata probe still reaches \CharMatchedGraphmetaAuc\%, so the
subset does \emph{not} meet its preset gate of low discrimination for both
probes, because parser-derived structural counts still separate the classes.
Only \CharMatchedN\ of its files fall into the test split. On them the full,
rule and no-semantic-edge variants reach macro-F1 of \CharMatchedFullFOne,
\CharMatchedRuleFOne\ and \CharMatchedNoESemFOne, respectively, but with six
positives and nine negatives the seed standard deviations are several points
wide. The caliper (0.56) was selected post hoc as the largest value keeping the
shallow-probe AUC at or below the 60\% gate, before any model was
evaluated on the subset; no caliper in the sweep satisfies the full gate (which
also requires a low graph-metadata AUC and a minimum file count). This subset
therefore neither supports nor refutes any comparative claim, and we report it
only as a diagnostic.

\section{Discussion}\label{sec:discussion}
\paragraph{Most of the score is shortcut-accessible.} Under a cluster-disjoint
split with canonicalized input, a random forest on character statistics comes
within a few macro-F1 points of every learned model. Reporting a near-ceiling
macro-F1 on such data therefore says little about whether a detector models
malicious behavior. The protocol makes the remaining, more informative
differences visible: low-FPR behavior, source transfer, and the split between
structure-preserving and packaging transformations.

\paragraph{What the structural model adds.} In-distribution, HiPaG's advantage
over the \emph{shortcut probes} is concentrated where false positives matter: a
lower FPR at high recall and higher precision at low prevalence than the
shallow probe and the flat GATv2. That advantage is not specific to program
structure, however: a fine-tuned CodeBERT, which uses no graph at all, matches
or exceeds HiPaG in the same low-false-positive regime
(Section~\ref{sec:r-rq1}). On the source-disjoint holdout the picture changes
rather than narrows: HiPaG's edge over the probes in the low-false-positive
regime disappears, and what remains --- the one place where the structural
model is distinguishable --- is a modest ranking improvement, on which CodeBERT
falls to last place. On structure-preserving transformations that leave character
statistics intact (L4), the shallow probe keeps its discrimination, so these
levels alone cannot isolate structural reasoning; the character-matched subset
was designed for that purpose but is too small at test time to be conclusive.

\paragraph{Why learned taint is redundant here.} Several mechanisms plausibly
explain the null result; we state them as hypotheses rather than findings.
(i) The information that the semantic edges encode is already available:
statement features flag seed sources, sinks and decoders, a dedicated feature
marks same-statement source-to-sink cases, and the file-level indicators record
\texttt{eval}-like calls and decoders. (ii) Candidates are generated by the
same static reachability that defines the weak labels, so the predictor mostly
re-scores pairs that the rule edges already connect; it is not given the
opportunity to recover dependencies that static analysis misses.
(iii) Identifier renaming (L1) is the one setting in which re-scoring could
help, because learned statement states are less tied to identifier names, and
it is the only level showing a (statistically unconfirmed) advantage. Decoupling
candidate generation from static reachability is a natural next step, but we do
not claim it would change the outcome.

\paragraph{Packaging is a boundary, not a level.} Packaging levels produce large
seed variance for every HiPaG variant, even with static deobfuscation, and the
shallow probe's AUC falls sharply once benign files are wrapped too. Static
deobfuscation keeps the graph-metadata probe from collapsing at these levels,
which again shows that parser-derived counts, not modelled data flow, carry much
of the surviving signal. Evaluations that wrap only malicious files would reward
wrapper detection, and evaluations that average packaging with
structure-preserving levels would hide this boundary. We recommend reporting the
two families separately.

\section{Threats to Validity}\label{sec:threats}
\paragraph{Construct validity.} Source, sink and decoder roles come from finite
seed lists; reachability-based weak labels are not verified taint flows, and
unlisted APIs or indirect behavior are missed. A statement that contains both
source and sink yields no inter-statement positive pair; such cases reach the
model only through a node feature. The semantic-edge ablation therefore
evaluates this particular learned-edge design, not taint analysis in general.
The control-flow and data-flow graphs are approximate.

\paragraph{Internal validity.} The local baselines are controlled
re-implementations, not reproductions of published systems, and GlareShell,
opcode-CNN and YARA are absent for the reasons in
Section~\ref{sec:setup}. Taint hyper-parameters were selected on validation
data, and RQ2 reuses RQ4 checkpoints without retraining. The character-matched
subset was constructed by searching over the matching caliper until the shallow
probe approached chance, so its operating point was chosen after inspecting
probe results; together with its small test portion this makes it a diagnostic
only. An exploratory analysis on files containing both a source and a sink is
not reported because that slice overlapped the training partition. The CodeBERT
baseline is also handicapped by its own input budget: the eight-window cap
discards the tail of the longest \CodeBertTruncatedTrainPct\% of training
files, so a configuration that read whole files might transfer differently on
the holdout. We did not run that configuration and claim no direction for it.

\paragraph{External validity.} The corpora are public collections of historical
PHP web shells and open-source benign code; private or recent web shells may
differ. The holdout is source-disjoint but from the same broad family, and
every sample is a single file, so neither cross-family transfer nor multi-file
web shells joined through \texttt{include} are tested. The transformations are
fixed rather than adaptive, and packaging marks the static-analysis boundary
rather than a robustness target.

\paragraph{Conclusion validity.} Seed aggregates are reported as mean and
sample standard deviation over a small number of seeds, without paired tests or
formal equivalence testing; ``on par'' and ``redundant'' mean
``indistinguishable within seed variation'', not proven equivalence. Base-rate
precision is derived from a single operating point and inherits its
uncertainty; at the lowest prevalence it is highly variable across seeds.

\section{Conclusion}\label{sec:conclusion}
We proposed a shortcut-controlled evaluation protocol for PHP web-shell
detection and applied it to HiPaG, a hierarchical program-graph model with a
learned taint-dependency predictor. The protocol shows that most
in-distribution performance is available from shallow features, that the only
advantage distinguishing the structural model is its slightly better ranking
(PR-AUC and macro-F1) on the source-disjoint holdout --- in-distribution it is
caught by a fine-tuned CodeBERT, and its low-false-positive edge over the
shortcut probes does not survive the change of source --- and that learned
taint edges are largely redundant,
helping only narrowly under identifier renaming. We recommend that web-shell
detection studies report shortcut probes, two-sided and family-separated
obfuscation results, source-disjoint evaluation and base-rate precision
alongside headline scores.

\bmhead{Reproducibility}
Every reported number is a mean $\pm$ sample standard deviation over
\RqOneSeeds\ seeds (0--4), except the taint hyper-parameter sweep, which used
\RqFiveSeeds\ seeds. The environment was Python 3.12.16, PyTorch 2.15.0 (CUDA
13.2 build), PyTorch Geometric 2.8.1 and Transformers 4.57.6, with PHP 8.5.4
and nikic/PHP-Parser 5.9.0 for parsing; training ran on one NVIDIA RTX 2080
Super Max-Q (8\,GB) with driver 580.178.04 and cuDNN 9.26.0, on an Intel Core
i7-10875H. Runs are seeded through \texttt{random}, \texttt{numpy},
\texttt{torch} and \texttt{torch.cuda}; HiPaG runs additionally set
\texttt{cudnn.deterministic} and disable \texttt{cudnn.benchmark}, while the
CodeBERT baseline runs under AMP \texttt{fp16}. We did not enable
\texttt{torch.use\_deterministic\_algorithms}, and \texttt{torch-scatter} is
not installed, so some PyTorch Geometric scatter reductions on the GPU are
order-dependent. We therefore do not claim bit-exact reruns, and report
dispersion across seeds instead of single-run figures. The CodeBERT baseline
is \texttt{microsoft/codebert-base} at revision \texttt{3b0952fe}, with
512-token windows at stride 384 capped at eight per file, averaged pooled
\texttt{[CLS]} vectors, AdamW at $2\times10^{-5}$, and the checkpoint chosen by
validation PR-AUC with early stopping (patience 5, at most 25 epochs). HiPaG
uses AdamW with the same checkpoint rule; its taint hyper-parameters
($k=\RqFiveChosenTopK$, $W=\RqFiveChosenWarmupEpochs$, with
$\tau_{\min}=\RqFiveChosenTauFloor$ fixed) were chosen by a validation macro-F1
sweep. A full manifest --- library versions, data hashes, split manifests and
per-seed run fingerprints --- is released with the code.

\bmhead{Ethical considerations and dual use}
All web-shell samples were treated as inert data. Files were parsed and
canonicalized statically with a PHP parser and never executed; no PHP runtime
interpreted any payload at any stage, and all processing ran in an isolated
environment rather than on any live server. The corpora are existing public
collections used under their original licenses; we neither collected new live
web shells nor deployed any sample. We did not test third-party systems, so no
responsible-disclosure process applies. Web-shell detection is dual-use: the
same study describes an obfuscation matrix and a static deobfuscator. We
release the detector, the evaluation protocol and the deobfuscation routines,
which are defensive. The obfuscation levels are built from standard, publicly
documented techniques (base64 and gzip packing, variable-function rewriting,
identifier renaming and dead-code insertion); we release them as evaluation
fixtures bound to our corpora, for reproducing the protocol, rather than as a
general-purpose web-shell generator, and we add no new malicious payloads
beyond transformations of samples already public.
